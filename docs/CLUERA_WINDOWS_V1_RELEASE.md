## Candidate

The immutable Windows x64 installer is `desktop/release-cluera-staging/1.0.8/ClueraAITestSetup-1.0.8.exe`. Its final size, SHA-256, Authenticode result and source/deployment evidence are recorded in [the final launch checklist](CLUERA_FINAL_LAUNCH_CHECKLIST.md). Never overwrite it, reuse a failed version or rename another build to this version.

This build includes the latest email/password and Google PKCE login, OS-encrypted refresh-token persistence, logout and isolated account workspaces. Signup and password recovery open the existing website. Tokens remain in the main process; the checkout browser receives only a non-secret account hint and independently authenticates.

The server remains authoritative for the once-only 900-second trial, pack/monthly allowances, reservations and usage settlement. After opening Buy Credits and returning to Windows, the app observes server balances every five seconds for at most two minutes, with single-flight requests and ownership checks. Active AI usage retains its existing 30-second reporting checks and trailing settlement read. Delayed or unavailable reconciliation never grants local time; use Refresh after the bounded window.

Gemini/Deepgram transport, both audio channels, streaming, cancellation, screenshots, selected context, local history/files, settings and shortcuts remain implemented. Provider gates are respected. No provider credential is bundled, no customer BYOK is introduced and no payment, provider spending or new trial is generated by packaging.

This candidate also fixes stalled updater requests/body cleanup, fences late workspace initialization after account changes, and provides an explicit retry when workspace loading fails. Builds clear only generated desktop output before compiling, so stale hashed renderer assets cannot enter a new installer. Archive verification compares every built file and all three bundled trust/configuration resources, in addition to product identity and the six Electron security fuses.

## Minimal owner acceptance

1. **Verify and install privately.** In PowerShell, run `Get-FileHash -Algorithm SHA256 -LiteralPath '<full path to ClueraAITestSetup-1.0.8.exe>'` and compare the complete hash with the final checklist. Check `Get-AuthenticodeSignature -LiteralPath '<same path>'`: this candidate must show `NotSigned`. Install normally as the intended Windows user. Do not disable antivirus, SmartScreen or organization policy. Record Windows version, display scaling, candidate hash and result.
2. **Accept account restoration and isolation.** Sign in with the existing account; confirm the same trial/balance as the website. Close/reopen and restart Windows. Test Google return/cancel, logout, offline retry and a second account: no prior user's sessions, documents, answers or credits may appear. Signup/reset are browser flows; do not repeat SMTP, Google provider or Admin/MFA setup.
3. **Accept payment synchronization once.** Follow [the existing billing guide](CLUERA_BILLING_FINAL_SETUP.md) for the retained Test order and approved purchaser. Return to Windows after the server-confirmed payment; verify exactly one pack, the original trial and matching website/Windows balances. Do not create a replacement order or grant minutes to bypass uncertainty. Monthly plans stay unavailable until their separate acceptance window.
4. **Finish private provider configuration, then test the actual device.** Follow the existing vault custody/provider steps in the final launch checklist. Only after deliberate bounded-spending approval, test interviewer system audio and candidate microphone separately and together, streaming/typed assistance, approved screenshots, selected documents, pause/cancel, disconnect/reconnect, expiry, exhausted balance and two-device settlement. Check 100%, 125%, 150% and 200% Windows scaling, footer controls, zoom/keyboard shortcuts, history and settings. Stop on cross-account exposure, incorrect deductions or unconfirmed provider settlement.
5. **Approve the exact candidate for distribution only after those results pass.** Record the hash and accepted feature scope. Test updating an accepted older build to this newer build; 1.0.8 cannot demonstrate an upgrade to itself. Preserve old installers and profiles. Uninstall/reinstall must not create another trial.

## Unsigned now, signed later

This direct GitHub candidate does not claim Microsoft Store distribution or a verified Windows publisher. The owner chose unsigned testing for now. Windows can show an unknown-publisher/reputation warning; the signed Cluera update manifest does not make the EXE Authenticode-signed.

For a later signed release, obtain signing credentials privately, configure the exact accepted publisher pin, build a **new immutable version**, verify timestamped Authenticode and the pinned publisher independently, and repeat update/device acceptance. The current packaging wrapper deliberately strips signing credentials and publish tokens: do not place certificate secrets in source or silently weaken the stable-channel publisher requirement.

References: [Electron signing](https://www.electronjs.org/docs/latest/tutorial/code-signing), [Electron ASAR integrity](https://www.electronjs.org/docs/latest/tutorial/asar-integrity), [GitHub release assets](https://docs.github.com/en/rest/releases/assets).

Test remains active; Live charging, public paid plans and provider spending retain their separate gates. A verified installer alone does not establish production readiness.
